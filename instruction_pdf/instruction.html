Часть 1. Как пользоваться приложением

1.1. Вход и пользователи

Откройте https://<ваш-домен>, войдите по логину/паролю. Все пользователи равноправны — ролей «администратор»/«только просмотр» нет.

Создать/изменить пользователя (на сервере, в папке проекта):

docker compose exec app node dist/lib/createUserCli.js <логин> <пароль>

Удалить:

docker compose exec db psql -U mailer -d mailer -c "delete from \"User\" where username='<логин>';"

1.2. Настройки (сделать один раз перед первой кампанией)

  • Почтовый ящик (SMTP/IMAP) — обязательно, от него уходят письма и в нём ищутся ответы. Хост подключения — не всегда домен почты: если сертификат почтового сервера провайдера выписан на другое имя (частый случай у shared-хостинга), нужен именно тот хостнейм (узнать: dig -x <IP почтового сервера>), иначе ошибка ERR_TLS_CERT_ALTNAME_INVALID. Кнопка «Изменить» — можно поправить любые поля, пароль оставить пустым — сохранится старый.
  • Фирменный бланк — логотип (jpg) и текст контактов для подвала письма. Один бланк = один логотип на всю кампанию; для разных логотипов под разные компании нужны отдельные кампании.
  • Нумерация исходящих писем — префикс (например «0210») и шаблон {prefix}/{counter}, счётчик растёт на 1 с каждым отправленным письмом (можно сбрасывать раз в год). Есть редактирование.
  • Отписавшиеся — кто отписался и когда, можно снять отписку вручную.

1.3. Создание кампании

«Кампании» → «Новая кампания»: название, тема и текст письма (шапка — исх. №, дата, должность/компания/ФИО, обращение — добавляется автоматически), опционально доп. варианты текста для авторотации (см. 1.5), ящик/бланк/нумерация, расписание (окно отправки, обед, интервал, часовой пояс), порог ротации.

Плейсхолдеры — в теме и тексте можно писать {{Компания}}, {{Должность}}, {{ФИО}}, {{Имя}}, {{Email}} — заменяются данными каждого получателя при отправке.

1.4. Получатели, запуск, ручные номера

  1. «Импортировать из Excel» (отдельная кнопка, не запуск!). Колонки: Компания, Должность, Фамилия И.О., Имя Отчество, Email. Битые email и дубли внутри файла пропускаются с предупреждением; повторный импорт не дублирует уже добавленных в кампанию.
  2. Ручные исходящие номера (опционально) — кнопка «Назначить исходящие номера вручную» раскрывает таблицу всех получателей с полем номера у каждого. Пусто — номер как обычно, автоматом по счётчику схемы. Вписали — уйдёт ровно этот номер, для этого одного получателя автосчётчик не расходуется, остальные продолжают нумероваться автоматически как ни в чём не бывало (ручной ввод не «продолжает» последовательность — для 1, 2, 3 подряд каждое число вписывается отдельно).
  3. «Запустить рассылку» — письма уходят по одному, по расписанию, автоматически.
  4. «Приостановить»/«Запустить» — пауза и продолжение в любой момент.
  5. «Повторить ошибки (N)» — вернуть в очередь письма, не ушедшие из-за временной ошибки.
  6. Кампания без получателей в очереди — статус done. Чтобы дослать ещё кому-то — импорт нового Excel в ту же кампанию + «Добавить получателей и продолжить» (уйдёт только новым).
  7. «Изменить» — та же форма, что при создании, с текущими значениями, работает в любом статусе. «Удалить» — сносит кампанию целиком вместе с получателями и историей (с подтверждением, необратимо).
  8. «Скачать отчёт (xlsx)» — в любой момент.

1.5. Ротация темы/текста каждые 50–100 писем

  • Ручной режим (по умолчанию). По достижении порога кампания встаёт на паузу «Требуется правка текста», оператор правит (или подтверждает как есть) и продолжает.
  • Автоматический. Заполните 1–4 доп. варианта при создании кампании: по достижении порога кампания сама переключается на следующий вариант по кругу, без остановки.

1.6. Отслеживание и отписка

  • Открытие — трекинг-пиксель, метрика оценочная (почтовые клиенты часто блокируют картинки по умолчанию).
  • Ответы — IMAP-поллинг раз в 5 минут, сопоставление по заголовкам письма. Работает при ответе через «Ответить» в почтовом клиенте.
  • Отказы (bounce) — тот же поллинг распознаёт письма о недоставке (mailer-daemon/postmaster) и отмечает отдельно от обычных ошибок отправки — видно в статистике и отчёте.
  • Отписка — ссылка в каждом письме, глобальная по email (на все кампании). Число отписавшихся из кампании видно в её статистике, полный список — в Настройках.

Часть 2. Полная передача заказчику

Сейчас приложение на сервере и почте исполнителя (VPS reg.ru 194.67.124.161, rassylka@vinakovlab.online). Для независимости заказчика (в т.ч. требование 152-ФЗ) нужно перенести на его собственную инфраструктуру.

2.1. Что должен завести заказчик

  1. Свой VPS в России — от 1 vCPU/2 ГБ RAM/Ubuntu 22.04 достаточно, хостер любой (reg.ru, Timeweb, Selectel, VK Cloud, Yandex Cloud).
  2. Свой домен (или поддомен) с доступом к DNS.
  3. Свой почтовый ящик с SMTP/IMAP на этом домене — Яндекс 360, VK WorkMail, либо почта на том же хостинге, где домен. Уточнить у провайдера: не блокирует ли SMTP с внешних IP по умолчанию (у reg.ru блокирует — снимается обращением в поддержку) и правильный хостнейм для подключения (см. 1.2).

2.2. Разворачивание на новом сервере

  1. Доступ к коду: передача прав на github.com/Hidan744/mailer заказчику, либо архив без истории git.
  2. На сервере: 
    git clone <адрес репозитория>
cd mailer
sudo bash deploy/setup-server.sh
cp .env.example .env
  3. Заполнить .env своими новыми значениями (не копировать значения исполнителя): POSTGRES_PASSWORD, CREDENTIALS_ENC_KEY, SESSION_SECRET — каждое сгенерировать отдельно (node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"), DOMAIN/PUBLIC_BASE_URL — домен заказчика, ADMIN_USERNAME/ADMIN_PASSWORD.
  4. docker compose up -d --build, открыть https://<домен> — HTTPS через Caddy сам.
  5. Подключить почтовый ящик, логотип/бланк, схему нумерации.
  6. Проверить SPF/DKIM/DMARC (обычно провайдер почты настраивает сам).
  7. Тестовая отправка на 2–3 адреса перед боевым запуском.

2.3. Что не передаётся

Сервер 194.67.124.161, ящик rassylka@vinakovlab.online, все текущие пароли/ключи — инфраструктура и секреты исполнителя на тестовый период. Заказчик заводит полностью свои.

2.4. Перенос тестовых данных (опционально, обычно не нужно)

docker compose exec db pg_dump -U mailer mailer > backup.sql
# перенести файл на новый сервер, затем:
docker compose exec -T db psql -U mailer mailer < backup.sql

2.5. Чек-лист передачи

  • VPS в РФ и домен у заказчика
  • Свой почтовый ящик с SMTP/IMAP
  • Код передан
  • Развёрнуто на новом сервере со своими секретами в .env
  • Домен указывает на сервер, HTTPS работает
  • Ящик подключён, тестовое письмо реально доставлено
  • SPF/DKIM/DMARC настроены
  • Логотип, бланк, схема нумерации заведены
  • Администратор заказчика входит и подтверждает всё лично
  • Сервер и почта исполнителя отключены
